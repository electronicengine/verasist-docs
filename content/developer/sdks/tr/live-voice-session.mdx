## Ön koşullar

`verasist-sdk[voice]` kurulu olmalı; `VERASIST_API_URL`, `VERASIST_API_KEY` ve `WORKFLOW_UUID` ayarlanmalı. Workflow’u ses modelleriyle yapılandırıp SDK araçlarını node’lara bağlayarak yayımlayın. Cihazdan signaling ve TURN erişilebilir olmalı.

`LiveSession` **Python** yardımcısıdır. Tarayıcı TypeScript tarafında REST ile oluşturulan tokenı `@verasist/sdk/video` içindeki `createDeviceVideoSession` ile kullanabilirsiniz. HTTP oturumu oluşturmak mikrofonu açmaz veya hoparlörden ses oynatmaz. Mikrofon için `aiortc` track’i ve gelen sesi tüketen bir uygulama bileşeni gerekir.

## Oturum oluşturup bağlanma

Aşağıdaki örnek ses dosyasını asistana gönderir ve yanıtı `assistant.wav` dosyasına kaydeder. `AUDIO_INPUT` var olan bir ses dosyası olmalıdır. Sistem mikrofonu için yerel FFmpeg/aiortc kurulumunuza uygun `AUDIO_INPUT` ve `AUDIO_FORMAT` değerlerini kullanın; örneğin Linux’ta PulseAudio cihazı. Sürücü ve ses oynatma uygulamanızın sorumluluğundadır.

Çalıştırmadan önce `sdk_status` şemasını [yayımlayıp ilgili node’a bağlayın](/developer/sdks/tools). Katalog yayımlamayı her aramada tekrarlamanız gerekmez.

```python
import asyncio
import os
import socket
from aiortc.contrib.media import MediaPlayer, MediaRecorder
from verasist_sdk import LiveSession, VerasistClient

async def main():
    with VerasistClient(base_url="https://app.verasist.ai") as client:
        session = LiveSession(client, initial_context={"device_name": socket.gethostname()})

        @session.tool(name="sdk_status", description="Read the connected device hostname")
        def status():
            return {"hostname": socket.gethostname()}

        player = MediaPlayer(os.environ["AUDIO_INPUT"], format=os.getenv("AUDIO_FORMAT"))
        recorder = MediaRecorder("assistant.wav")
        recording_tasks = []
        if player.audio is None:
            raise RuntimeError("AUDIO_INPUT must contain an audio track")

        @session.on_track
        def on_track(track):
            if track.kind == "audio":
                recorder.addTrack(track)
                recording_tasks.append(asyncio.create_task(recorder.start()))

        @session.on_transcript
        def on_transcript(event):
            if event["final"]:
                print(event["role"], event["text"])

        @session.on_connection_state
        def on_connection_state(state):
            print("WebRTC:", state)

        try:
            await session.connect(
                workflow_uuid=os.environ["WORKFLOW_UUID"],
                tracks=[player.audio],
                call_context_vars={"locale": "en"},
                ice_timeout_secs=30,
            )
            print("Run:", session.workflow_run_id)
            print("Closed:", await session.wait_closed())
        finally:
            await session.close()
            if recording_tasks:
                await asyncio.gather(*recording_tasks)
            await recorder.stop()
            player.audio.stop()

if __name__ == "__main__":
    asyncio.run(main())
```

Hoparlörden ses vermek için gelen track’in `recv()` karelerini uygulamanızın ses çıkışına aktarın.

## Oturum yaşam döngüsü

| Metot/alan | İşlev |
| --- | --- |
| `await session.start(workflow_uuid=...)` | HTTP oturumu oluşturur; `session_token` ve `workflow_run_id` saklanır, henüz medya bağlantısı yoktur |
| `await session.connect(workflow_uuid=..., tracks=[...])` | Gerekirse oturum açar, TURN bilgilerini alır, signaling açıp WebRTC teklifi gönderir |
| `await session.wait_closed()` | Bitiş, bağlantı hatası veya yerel kapatmayı bekler; varsa kapanış payload’ını verir |
| `await session.close()` | Signaling ve peer connection kaynaklarını kapatır; `finally` içinde kullanın |
| `session.pc` | Tanılama için alttaki peer connection |

API Trigger kullanacaksanız `workflow_uuid` yerine `trigger_uuid` verin; ikisini birlikte vermeyin. `start()` ayrı çağrılmışsa aynı session üzerinde `connect(tracks=[...])` yeterlidir. Her yeni konuşma için yeni `LiveSession` oluşturun.

`connect()` medya yolunun hazır olduğunu garanti etmez. `on_connection_state` olayını izleyin. ICE watchdog varsayılanı 30 saniyedir; `ice_timeout_secs=None` kapatır. `wait_closed()` sonucundaki `ice_timeout`/`ice_failed` durumlarında TURN erişimini ve cihaz ses ayarlarını kontrol edin.

## Cihaz araçları

`@session.tool(name=..., description=..., parameters=...)` senkron veya asenkron fonksiyon kaydeder. Varsayılan ad fonksiyon adıdır; varsayılan parametre şeması boş nesnedir. Argümanlar keyword argüman olarak verilir. JSON’a çevrilebilir sonuç döndürün; handler istisnaları araç hatası olarak iletilir.

Araçları `start()`/`connect()` öncesinde kaydedin. Sonradan yerel fonksiyon eklemek sunucudaki oturum listesini güncellemez. Bloklayan cihaz/dosya işini async handler içinde `asyncio.to_thread()` ile yürütün; senkron handler doğrudan çağrılır ve signaling’i bekletebilir. Cihaz komutlarını uygulamanızda doğrulayın.

LLM yalnızca **aktif node’a bağlı** ve oturumda kayıtlı araçları kullanabilir. Katalog kaydı tek başına yeterli değildir.

## Transkript ve ses olayları

Callback’ler senkron bildirimlerdir. Asenkron iş için `asyncio.create_task()` kullanın ve görev hatalarını yönetin.

- `on_transcript`: `{role, text, final}`. Kullanıcı metni ara sonuç olabilir; asistan metni finaldir.
- `on_connection_state`: peer connection durum metni.
- `on_voice_event`: `{type, payload}`. Desteklenen olaylar: `rtf-bot-started-speaking`, `rtf-bot-stopped-speaking`, `rtf-bot-interrupted`, `rtf-user-mute-started`, `rtf-user-mute-stopped`, `rtf-user-turn-started`, `rtf-user-turn-final`, `rtf-camera-attachment`.

## Kamera görüntüsü gönderme

Oturum bağlandıktan sonra JPEG, PNG veya WebP olarak kodlanmış baytları gönderin; ham piksel verisi göndermeyin:

```python
from pathlib import Path
from verasist_sdk import LiveSession

async def send_snapshot(session: LiveSession, image_path: str):
    return await session.send_image(
        image_bytes=Path(image_path).read_bytes(),
        mime_type="image/jpeg",
        prompt="Describe what is visible.",
        trigger_response=True,
        timeout=30,
    )
```

Dönen sonuç görüntünün kabul edildiğini bildirir, asistanın cevabı değildir. Cevap normal transkript/ses olaylarından gelir. Sunucu boyut, çözünürlük, biçim ve hız sınırlarını uygular. Uyumlu çok modlu model gerekir; bu API sürekli video taşımaz.

Devam eden bir yanıta bağlam eklerken ikinci yanıtı tetiklememek için `trigger_response=False` kullanın.

## Görüntüyü belirli kullanıcı turuna bağlama

Uyumlu STT/LLM/TTS ve cihaz Gemini Live workflow’larında bağlantı sonrasında `await session.configure_camera_turns(True)` çağırın. `rtf-user-turn-started` olayında `event["payload"]["turn_id"]` değerini alıp kamera işini başlatın:

```python
from verasist_sdk import LiveSession

async def attach_camera_turn(session: LiveSession, turn_id: str, jpeg: bytes | None):
    try:
        if jpeg is not None:
            await session.send_image(
                image_bytes=jpeg,
                mime_type="image/jpeg",
                turn_id=turn_id,
                trigger_response=False,
            )
    finally:
        await session.complete_camera_turn(turn_id)
```

Görüntü alınamasa da turu tamamlayın. İlk turn ID’sini koruyun; geciken görüntüyü başka tura atamayın. Desteklemeyen sunucu/workflow yapılandırmayı hata ile reddeder. Sonucu `rtf-camera-attachment` olayından izleyin.

## Sesli, görüntülü veya text seçin

| Görüşme | Python | TypeScript | REST |
| --- | --- | --- | --- |
| Sesli | `LiveSession(client)` | Run REST + `autoStartCamera: false` ile `createDeviceVideoSession` | `run_type: "voice"` |
| Sesli ve görüntülü | `LiveSession(client, mode="video_session")` | Run REST + `createDeviceVideoSession` | `run_type: "video"` |
| Text chat | `client.text_sessions` | `client.textSessions` | `/api/v1/public/agent/workflow/{workflow_uuid}` ve `/api/v1/public/agent/runs/{run_id}` |

Sesli ve görüntülü oturumlar yayımlanmış workflow’u kullanır. Görüntülü oturumdan önce workflow ayarlarında **Video session** seçeneğini açıp görüntü girdisi destekleyen bir görsel model seçin. Kamera, ekran veya ikisine birden izin verin. Mevcut sesli/text oturumun modu değişmez; video için yeni oturum oluşturun.

## REST ile canlı oturum oluşturun

Organizasyon API anahtarını uygulama sunucunuzda tutun. Workflow UUID ile çağırın:

```bash
curl -X POST 'https://app.verasist.ai/api/v1/public/agent/workflow/YOUR_WORKFLOW_UUID' \
  -H "X-API-Key: $VERASIST_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"run_type":"video","initial_context":{"locale":"tr"}}'
```

Alternatif olarak API Trigger node UUID’siyle `POST /api/v1/public/agent/{uuid}` kullanın. Yanıtta `session_token`, `workflow_run_id`, `expires_at` ve varsa `scheduling` bulunur. Kuyruğa alınan başlangıç HTTP 202 dönebilir; yeni oturum açmak yerine aynı oturumun hazır olmasını bekleyin. Scheduling türü video için `video`, ses için `webrtc`, text için `chat` olur.

REST oturumu oluşturur. Ses WebRTC, görsel kareler signaling üzerinden taşınır; HTTP yanıtı kamerayı açmaz. Alanları ve Try it formunu [Oturum API referansında](/api-referansi/runs/trigger-workflow) inceleyin.

## Tarayıcıda sesli ve görüntülü oturum

`createDeviceVideoSession` export eden bir SDK paketi kullanın. Kurulu paketiniz bu yardımcıyı içermiyorsa mevcut `VideoSession({signalingUrl, iceServers, autoStartCamera})` constructor’ına `wss://YOUR_API_HOST/api/v1/ws/device/signaling/SESSION_TOKEN` ve `GET /api/v1/public/agent/runs/{session_token}/turn-credentials` yanıtındaki TURN bilgilerini verin. Organizasyon API anahtarını signaling URL’sine koymayın.

Tokenı SDK ile sunucuda oluşturun, yalnızca tokenı kimliği doğrulanmış tarayıcıya iletin:

```typescript
import { VerasistClient } from "@verasist/sdk";

const client = new VerasistClient({ baseUrl: "https://app.verasist.ai" });
const result = await client.startRunByWorkflow(workflowUuid, {
  body: { run_type: "video" },
});
// result.session_token değerini yetkili tarayıcıya iletin. API anahtarı sunucuda kalır.
```

Tarayıcıda bir audio elementi ve sessiz, playsinline video elementi kullanın:

```typescript
import { createDeviceVideoSession } from "@verasist/sdk/video";

const session = await createDeviceVideoSession({
  apiBaseUrl: "https://app.verasist.ai",
  sessionToken, // Uygulama sunucunuzdan alınan token.
});
session.addEventListener("audio", (event) => {
  audioElement.srcObject = new MediaStream([(event as CustomEvent<MediaStreamTrack>).detail]);
});
session.addEventListener("stream", (event) => {
  previewElement.srcObject = (event as CustomEvent<{stream: MediaStream | null}>).detail.stream;
});
session.addEventListener("status", (event) => console.log((event as CustomEvent).detail));
await session.connect();
// Uygulama butonlarına bağlayın:
// await session.startVideo("screen");
// await session.stopVideo(); // Ses devam eder.
// session.close();
```

Sesli kullanımda sunucuda `run_type: "voice"`, tarayıcı factory’sinde `autoStartCamera: false` seçin. Sesli oturumda `startVideo` çağırmayın. Embed yetkilendirmeli dağıtım için aynı SDK girişinden `createVideoSession({apiBaseUrl, embedToken})` kullanılmaya devam eder.

HTTPS veya localhost kullanın. Video capabilities hazır olunca kamera bir kez başlar. Kamera izni reddedilirse unavailable durumu bildirilir, ses kapanmaz. Ekran paylaşımı kullanıcı eylemiyle başlatılmalıdır ve tarayıcı desteğine bağlıdır. Factory kısa ömürlü token ile TURN bilgilerini alır; HTTP 503 durumunda STUN kullanılır, geçersiz/süresi dolmuş token hata verir. `close()` mikrofon, kamera/ekran, peer connection ve signaling kaynaklarını kapatır. Asistan sesini oynatmak tarayıcı autoplay kuralları nedeniyle kullanıcı eylemi gerektirebilir.

## Python ile sürekli görsel gözlem

Kamera yakalama veya ekran görüntüsü üretimi uygulamanıza aittir; SDK kamerayı otomatik açmaz. `connect` öncesinde `LiveSession(client, mode="video_session")` oluşturun. Bağlantıdan sonra uygulamanızın JPEG verisini kullanın:

```python
capabilities = await session.video_capabilities()
if capabilities["enabled"] and capabilities["allow_camera"]:
    await session.configure_video("camera")
    await session.send_video_frame(jpeg_bytes, "image/jpeg")
    # Yeni kareleri capabilities["interval_seconds"] aralığından sık göndermeyin.
    await session.configure_video(None)  # Görüntüyü durdurur; ses devam eder.
```

İzin veriliyorsa uygulamanızın ekran görüntüleri için `configure_video("screen")` kullanın. SDK kareleri güncel kaynak ve generation ile ilişkilendirir. Video durdurulduktan sonra `send_video_frame` gönderimi reddeder. `on_voice_event`, analiz ve hata ayrıntıları dahil `video-status` olaylarını alır. `capabilities["record_video"]` kayıt izni veriyorsa encoder’ınız sıralı `send_video_recording_chunk(data, sequence, mime_type="video/webm")` parçalarını gönderebilir. Ses ve video kaydı workflow ayarlarına bağlıdır.

Text oluşturma, çalıştırma, mesaj revision’ları, streaming ve kapatma için [Text oturumlarını](/developer/sdks/text-session) kullanın. Text, live-session tokenı veya WebRTC kullanmaz.


Başlatma artık ortak run endpointinde `run_type: "voice" | "video" | "text"` ile yapılır. Alan verilmezse mevcut telefon/kanal davranışı korunur. Text için UUID `request_id` gerekir; mesajlar ve kapatma `/api/v1/public/agent/runs/{run_id}` altında çalışır. Eski oturum adresleri yalnızca uyumluluk alias’ıdır.
