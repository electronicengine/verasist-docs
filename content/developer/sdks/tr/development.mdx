## Ön koşullar

Verasist repository’si, backend Python ortamı, Node/npm ve SDK geliştirme bağımlılıkları gerekir. Veritabanı kullanan testlerde `api/.env.test` kullanın; geliştirme/canlı kimlik bilgilerini kullanmayın. Yerel kurulum için repository README dosyasını izleyin.

## Kaynak sahipliği

| Konum | Sorumluluk |
| --- | --- |
| `sdk/python/src/verasist_sdk/client.py` | Python HTTP, kimlik doğrulama ve kullanım yardımcıları |
| `sdk/python/src/verasist_sdk/live_session.py` | WebRTC, araç yönlendirme, olaylar ve görüntüler |
| `sdk/typescript/src/client.ts` | TypeScript HTTP ve kullanım yardımcıları |
| `sdk/typescript/src/text-session.ts` | Metin oturumu metotları, `dispatchTextTool` |
| SDK `workflow` modülleri | Workflow builder ve doğrulama |
| `api/services/workflow/dto.py`, `node_specs/` | Node alanları ve editör metadata’sı |
| `api/sdk_expose.py` | Endpoint’in SDK üretimine dahil edilmesi |
| `sdk/codegen/client_codegen.py` | Ortak REST metodu üreticisi |
| `_generated_client`, `_generated_models`, `typed/` | Üretilen dosyalar; elle değiştirmeyin |

Python `typed/_base.py` elle yazılmıştır. `client.py`/`client.ts` daha kolay kullanım için üretilmiş metodu override edebilir. Yeni API route’u eklemek kendiliğinden ses/metin oturumu yardımcısı oluşturmaz.

## Kaynaktan kurulum

Repository kökünden:

```bash
python -m pip install -e './sdk/python[voice,dev]'
npm --prefix sdk/typescript ci
npm --prefix sdk/typescript run build
```

TypeScript tüketici uygulaması için paket üretme:

```bash
cd sdk/typescript
npm run build
npm pack
```

Oluşan `.tgz` dosyasını uygulamaya kurup lockfile’ı güncelleyin. `vendor/` tarball’ı kullanılıyorsa onu da değiştirin ve uygulamayı yeniden build edin. Python wheel için repository kökünde `python -m pip wheel ./sdk/python --no-deps --wheel-dir /tmp/verasist-sdk-wheels` çalıştırıp oluşan wheel’i tüketici ortama kurabilirsiniz.

Bu işlemler npm/PyPI yayını yapmaz. Sürüm artırma, registry kimlik bilgileri ve release ayrı işlemlerdir. Yerel kaynakta eklenen metodun herkese açık registry paketinde bulunduğunu varsaymayın.

## REST metodu ekleme

1. Backend request/response modellerini tanımlayıp organizasyon sahipliğini denetleyin.
2. Ortak SDK yüzeyine ait route’a `sdk_expose(method="your_method", description="...")` ekleyin.
3. İş mantığını servis katmanında, veritabanı erişimini DB client’ta tutun.
4. Doğrulama, sahiplik ve davranış testlerini ekleyin.
5. İki SDK’yı yeniden üretip istek biçimlerini ve tipleri test edin.

Üretici Python snake_case ve TypeScript camelCase metotları oluşturur. Toolset route’ları ortak API ve kolay kullanım wrapper’ı için örnektir. `textSessions` ayrı, elle yazılmış bir yardımcıdır; tüm uygulama endpoint’lerini otomatik üretilen yüzeye eklemek gerekmez.

## Kod üretimi

Backend ortamını etkinleştirin. Betik varsa `api/.env` yükleyerek backend yapılandırmasını import eder; migration çalıştırmaz. Test ortamını kurmanın yerine geçmez.

```bash
./scripts/generate_sdk.sh
npm --prefix ui run generate-client
```

İlk komut tipli node’ları, SDK OpenAPI modellerini, REST istemcilerini ve `docs/api-reference/openapi.json` dosyasını üretir. `datamodel-codegen`, repository’nin `.mts` betiklerini destekleyen Node ve SDK `openapi-typescript` bağımlılığı gerekir. İkinci komut tam OpenAPI’den UI istemcisini üretir.

Üretilen farkları inceleyin. Node açıklaması/varsayılanı iki dili de etkileyebilir. Eksik/null/boş değer ayrımını koruyun; SDK araçları için üçü de runtime’da erişimsizdir, açıkça verilen boş liste kaydetme/yüklemede korunmalıdır.

## Test

Repository kökünde Python ortamı etkinken:

```bash
set -a
source api/.env.test
set +a
python -m pytest api/tests/test_sdk_toolset.py api/tests/test_sdk_text_tools.py api/tests/test_sdk_sync.py api/tests/test_verasist_sdk.py api/tests/test_verasist_sdk_typed.py sdk/python/tests/test_live_session.py
npm --prefix sdk/typescript test
npm --prefix sdk/typescript run typecheck
```

`test_sdk_sync.py` tipli dosyaların node-spec üreticisiyle eşleştiğini denetler. Ses testleri signaling/medyayı taklit eder; gerçek mikrofon, hoparlör, TURN veya sağlayıcı davranışını kanıtlamaz. Medya değişikliklerinde ayrıca cihaz testi yapın. Metin callback’lerini gerçek veriyi değiştiren uygulamadan önce kontrollü endpoint ve doğru origin politikasıyla deneyin.

## Sunucu ve istemci sürümlerini eşleme

Ana Docker Compose kurulumu için:

```bash
docker compose up -d --build api ui
```

API açılışında Alembic, varsayılanı `head` olan `ALEMBIC_TARGET_REVISION` hedefine ilerler. Yeni kodda beklenen sütun yoksa eski sürüme sabitleyen override olup olmadığını kontrol edin. API/UI build, tüketici uygulamanın Python ortamını veya vendored `.tgz` paketini değiştirmez.

Kataloğu yayımladıktan sonra editörü yenileyin, araçları node’lara bağlayın, kaydedip yayımlayın ve yeni oturum başlatın. Farklı node’larda farklı seçimlerle, başka node’a ait aracın çağrılamadığını test edin.
