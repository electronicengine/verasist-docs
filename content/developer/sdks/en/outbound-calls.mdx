---
title: "Place an outbound call"
description: "Trigger a Verasist voice agent to call a phone number from the SDK"
---

Use the SDK to place a test outbound call from a specific agent to a phone number. This is the same endpoint used by the **Test Call** button in the Verasist UI.

## Prerequisites

- A Verasist [API key](/developer/configurations/api-keys) exported as `VERASIST_API_KEY`
- An existing workflow (you need its numeric ID)
- A configured telephony provider — see [Telephony](/guides/integrations/telephony/overview) for Twilio, Vonage, and other setups

The test-call endpoint creates new runs with `use_draft=True`. It can therefore test an unpublished draft; do not confuse it with published-only application text sessions. If you pass an existing `workflow_run_id`, the endpoint operates on that run instead.

## Place the call

<CodeGroup>
```python Python
from verasist_sdk import VerasistClient
from verasist_sdk._generated_models import InitiateCallRequest

with VerasistClient(base_url="https://app.verasist.ai", api_key="YOUR_API_KEY") as client:
    client.test_phone_call(
        body=InitiateCallRequest(
            workflow_id=123,
            phone_number="+14155551234",
        )
    )
```
```typescript TypeScript
import { VerasistClient } from "@verasist/sdk";

const client = new VerasistClient({ baseUrl: "https://app.verasist.ai", apiKey: "YOUR_API_KEY" });

await client.testPhoneCall({
    body: {
        workflow_id: 123,
        phone_number: "+14155551234",
    },
});
```
</CodeGroup>

## Inspect the run

Every call creates a **run** you can inspect afterwards. See [Calls & runs](/developer/core-concepts/calls-and-runs) for what's tracked, or use the [Runs API](/api-reference/agents/runs/list) to list and fetch runs programmatically.

## Bulk campaigns

For placing many calls at once (say, from a CSV), use [Campaigns](/developer/core-concepts/campaigns) rather than looping over `test_phone_call` — campaigns handle pacing, retries, and progress tracking.

## Choose a telephony configuration

Use `telephony_configuration_id` to select an organization-owned configuration and `from_phone_number_id` when you need a particular configured caller number. Both fields are optional; the backend resolves defaults when omitted. Use a valid target number and a provider that supports the requested call.

```typescript
import { VerasistClient } from "@verasist/sdk";

async function callWithProvider(client: VerasistClient, workflowId: number,
  phoneNumber: string, configurationId: number) {
  return client.testPhoneCall({ body: {
    workflow_id: workflowId,
    phone_number: phoneNumber,
    telephony_configuration_id: configurationId,
  } });
}
```

Inspect the returned JSON and workflow run history; a request being accepted is not proof that the recipient answered. Do not automatically retry a timed-out initiation request: it may already have placed a call.

A phone call does not establish a Python device session or text callback transport. Publishing SDK tool schemas by itself cannot make application handlers callable on an ordinary telephony run. Server-side workflow tools continue to run through their configured integrations.
